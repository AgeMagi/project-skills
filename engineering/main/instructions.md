## Engineering skills

Load the matching skill before starting, without waiting to be asked:

- Stress-testing a plan, decision or design: `grilling`; when terms or decisions get settled, `domain-modeling` as well.
- Splitting agreed work into tickets: suggest `/to-tickets` (it only runs when the user invokes it). For a design grilling that should also write the glossary and ADRs, suggest `/grill-with-docs`.
- Building or fixing test-first: `tdd`. A hard bug, flaky test or performance regression: `diagnosing-bugs` before changing code.
- A design question that needs something concrete to react to: `prototype`. Facts from docs, APIs or source code: `research`.
- Reviewing a PR or diff: `review-fix-pr-frontend` or `review-fix-pr-backend`, by the code it touches.
- Delivering a Linear issue: `linear-task-workflow`.
