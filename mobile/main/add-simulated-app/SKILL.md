# Add a simulated app format

Use only when the user requests a new simulated app/format in a product that supports this capability. Read its preview architecture and design, model, persistence, export and disclosure contracts. Do not assume another project's enums, paths, assets or fixed iOS target exist here.

Define the new surface, supported platforms/states, behavior and formats to preserve, allowed integration files and evidence. An additional platform or feature in an existing simulated app is usually an extension of that app's contract, not a new app.

Research the target with public observable/official evidence using available tools. Record URLs, dates, platform/version, observations and uncertainty. Build original rendering and assets; do not copy another project's branding. If a research skill is installed, it can support this step but is not required.

Write a compact layout contract in the project's established documentation location: shared versus independent model, canvas/density/safe areas, regions, typography/tokens, metadata placement lanes, overflow, long-content pressure, disclosure and export clearance. Keep app-local geometry separate from shared conventions. Update existing routing docs where they exist; do not invent mandatory scripts.

Integrate through existing dispatch, draft codec/controller, editor, preview, deterministic fixtures and export paths. Map shared data intentionally; a shared timestamp does not require all formats to show it. Preserve stored drafts and unrelated renderers. Keep new tokens local unless shared behavior actually changes.

Verify dispatch and persistence, important geometry and affected shared consumers. Use goldens and real runtime reference captures where appropriate. Update the shipped contract and its source/test ownership in the same change. Report supported states, evidence and any fidelity gaps.
